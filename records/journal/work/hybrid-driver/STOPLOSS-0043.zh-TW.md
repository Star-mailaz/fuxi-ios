# 0043 停損報告（2026-11-16 00:30）

停損規則（2026-11-15 約定）：≥95 Hz 繼續；≤90 Hz 由使用者決定「做 P3（Turnip 直出 PM4）」或「停在約 88 Hz 轉做可用性」。判定看 0043 的 hyb8s（重疊要先拉高）與 hyb8i。

## 1. 結果：六趟 p1 全部 ≤90 Hz

| 版本 | 內容 | 乾淨窗口 Hz（第 1／2 趟） | 重疊率 | 最高溫 |
|---|---|---|---|---|
| hyb8 | commit 交給 worker（對照組） | 88.1 / 88.5 | 3.4% | 70.6 / 74.2 °C |
| hyb8s | ＋補丁 0023：有 handler 的 commit 也重疊 | 88.2 / 88.5 | 96.8 / 96.9% | 74.9 / 73.8 °C |
| hyb8i | ＋fence 改睡在 GPU 中斷（bit 26） | 88.4 / 88.1 | 3.3 / 3.2% | 71.0 / 71.0 °C |

- 三者差距都在 ±0.4 Hz 內，單次開機誤差約 ±2，等於沒差。
- hyb8s：CA 97% 的 commit 已經不等 GPU 先跑，Hz 不變 → 「CA 等 GPU」不是瓶頸。
- hyb8i：中斷路徑正常（每趟約 2.4 萬次中斷、零競態），Hz 與溫度都不變 → 核心輪詢不是瓶頸，也不是發熱來源。
- 六趟都沒有 DeviceLost。USB 斷 2 次，都在腳本跑完後，1 秒重連，資料完整。

## 2. 為什麼卡在 88：這支腳本的時間花在哪（hyb8s）

| 類別 | 佔腳本時間 | 說明 |
|---|---|---|
| 每週期都出幀 | 66–68% | 正常 |
| 慢 2–3 週期 | 約 4.4% | 渲染端趕不上，GPU 路徑變快只救得回這塊 |
| 4+ 空檔（29–50 ms） | 10–17% | 每趟約 930 次，見下 |
| idle（≥50 ms） | 11–19% | 腳本每步之間本來就停，約一步一次 |

- **4+ 空檔不是渲染造成的**：從 0036 hyb3（77.5 Hz）到 0043 hyb8s（88.5 Hz），渲染端重幀（encode ≥10 ms）從 2518 降到約 100、2 週期空檔從 2284 降到約 600，4+ 空檔一直是 835–958 次。每 600 幀區塊的 4+ 跟「每步結束」同步出現，跟重幀沒有一致關聯。
- 所以不管 GPU 多快，這支腳本的 Hz 上限約 **90.5**（2–3 週期全部救回）；現在 88.3 已到上限的約 97%。95 Hz 的門檻在這支腳本上本來就到不了。
- 4+ 空檔是「動畫收尾位移不到一個像素、本來就不用畫」還是「app 端 CPU 慢」，現有資料分不出來。

## 3. 螢幕上實際看到的：頓一下從哪來

- 每個版本都有 3.5–4.8% 的幀畫完沒顯示（被下一幀取代），從 0025 就這樣；螢幕實際 Hz ≈ 指標 × 0.964（hyb8 約 84.6）。
- hyb8 每趟約 2190 次「同一張畫面顯示兩個週期」，其中只有約 610 次是 CA 送晚；另外**約 1600 次是 CA 準時送出，但那幀在 worker 編碼＋GPU 做太久，趕不上 TE**。這才是肉眼會看到的頓點，而且 Hz 指標看不到。
- 趕不上的是中、重負載幀：encode ≥6 ms 的重幀每趟約 440 個（平均 8.4–10.7 ms，其中約一半在建材質／IOSurface import；85% 重幀建材質、約 65% 做 import），4–6 ms 的中負載幀每趟約 900 個。

## 4. P3 值不值得

P3（Turnip 私有入口直接產生 PM4，估 1–2 週，要重建 Mesa、GMEM／sysmem 都要驗）省的是「每筆 draw 的錄製時間」：

- 輕幀已經很便宜（每幀約 0.8 ms、每筆 draw 約 8 µs），P3 幾乎沒得省。
- 重幀扣掉建材質／import 後，draw＋pass 約 4–5 ms；P3 樂觀估省 1.5–2 ms，只能把差一點就趕上的那部分幀救回來。
- 平均 Hz 最多再 +1～2（上限 90.5 不變）；頓點大概減少一部分，但建材質／import 那一半碰不到。

**建議：不做 P3，GPU 這條線停在約 88 Hz（螢幕約 85），轉做可用性。**

如果之後還想在 GPU 上花一點時間，比 P3 便宜、對頓點更直接的兩件事（各約半天到一天＋一趟開機）：

1. **4+ 空檔分類**：前端記錄每個腳本步驟的空檔序列。若是 app 端 CPU 慢，槓桿在 CPU 排程／頻率，不在 GPU。
2. **重幀材質／import 重用**：重幀一半時間在建材質與 IOSurface import，快取可重用的就直接減少頓點。
